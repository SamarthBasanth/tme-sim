# Landscape survey: public serial/consecutive spatial-transcriptomics section datasets, as inputs for tme-sim's first 3D reconstruction

**Purpose.** tme-sim's stated 3D strategy is to build the third dimension itself, by registering multiple 2D spatial-transcriptomics sections cut at known z-spacing through the same tissue block — the way PASTE2 and STalign do it — rather than waiting for a vendor to ship native 3D spatial transcriptomics (confirmed absent in `results/landscape_spatial_platforms.md`). This document catalogs every publicly downloadable serial-section spatial-transcriptomics dataset located, across any cancer type and any platform, and ranks them by how fast tme-sim could actually register one.

**Method.** Worked serially (no sub-agent fan-out), using PubMed/PMC full text (via the PubMed MCP), 10x Genomics' own dataset pages, Zenodo, CNGB/STOmics, and direct `curl -I` liveness checks against raw download URLs. Primary strategy per the task brief: read the actual PASTE2 and STalign papers' Methods/Data sections to find exactly which public datasets their own validation examples came from — those datasets are, by construction, real serial-section spatial data that a registration pipeline has already been proven to work on. Everything below is cited; anything not confirmed by a primary source is marked **UNVERIFIED**.

**ingest.py capability check (so "usable today" means something).** Read directly from `/Users/samarthbasanth/tme-sim/tmesim/data/ingest.py`: the module natively recognizes three layouts — `xenium` (a per-cell centroid table + `cell_feature_matrix` MEX triple, optionally `gene_panel.json`), `visium` (Space Ranger output: `spatial/` dir with `tissue_positions[_list].csv` + `scalefactors_json.json`, plus a `filtered_feature_bc_matrix`/`raw_...` MEX triple), and `mex` (a bare MEX triple + any coordinates CSV/TSV as a generic escape hatch). There is no explicit Visium HD-specific branch in the code (grepped for `"visium hd"`/`"HD"` — no hits), so Visium HD compatibility is **UNVERIFIED**, not confirmed, despite superficial layout similarity. CosMx, Stereo-seq, and MERFISH/Vizgen raw outputs are **not** one of the three recognized layouts — they would need to be reshaped into the generic MEX-plus-coordinates form, or a new loader written, before `ingest()` would accept them.

## Ranked findings

### TIER 1 — usable today, zero new ingestion code, cancer-relevant: Janesick et al. 2023 breast cancer serial-section Xenium + Visium CytAssist (Sample #1)

This is the dataset STalign itself validated 3D-registration-adjacent alignment on (see below), and it is a direct hit on tme-sim's two natively-supported platforms, from the same FFPE tumor block.

- **Paper**: Janesick A, et al. "High resolution mapping of the tumor microenvironment using integrated single-cell, spatial and in situ analysis." *Nature Communications* 14, 8353 (2023). DOI: [10.1038/s41467-023-43458-x](https://doi.org/10.1038/s41467-023-43458-x). PMID: [38114474](https://pubmed.ncbi.nlm.nih.gov/38114474/), PMC: [PMC10730913](https://pmc.ncbi.nlm.nih.gov/articles/PMC10730913/) — verified by direct full-text fetch via PubMed MCP.
- **Cancer type**: breast, Sample #1, TNM stage T2N1M0, ER+/HER2+/PR−. FFPE block collected 2021-07-26 (Discovery Life Sciences). Quote from the paper: *"single cell, spatial and in situ technologies on serial sections of an FFPE-preserved breast cancer block."*
- **Sectioning / z-spacing (verbatim from Methods, verified by direct fetch)**: *"25 μm FFPE curls were collected into a tube prior to serial sectioning for Visium CytAssist and Xenium (two replicates of 5 μm sections for each spatial platform), then an additional 25 μm FFPE curl was collected into the same tube reserved for scFFPE-seq."* So: the block was cut in the order scFFPE-seq curl (25 µm) → Xenium/Visium serial 5 µm sections (2 replicates each) → scFFPE-seq curl (25 µm). Each Xenium/Visium section is confirmed **5 µm thick**, and the two Xenium replicates are confirmed **serial** (adjacent in the cutting sequence) — but the exact number of microns separating Replicate 1 from Replicate 2 specifically (i.e., how many other sections/curls sat between them) is **UNVERIFIED**; the paper states the pattern, not the precise offset in microns.
- **Reproducibility confirmed by the paper itself**: *"Analysis of two serial sections demonstrated the reproducibility of the technology, with the replicates having cell type proportions that were nearly identical and transcript counts that were highly correlated (r = 0.99)."*
- **Platform / panel**: Xenium In Situ, 313-gene targeted panel (custom-selected from breast cancer cell atlas data). Visium CytAssist on the same block uses the whole-transcriptome FFPE probe set (18,536 genes / 54,018 probes) — same probe set as the paired scFFPE-seq, so the Visium layer is effectively whole-transcriptome.
- **Cell/spot count**: Xenium — 167,885 total cells, 36,944,521 total transcripts (Q≥20), median 166 transcripts/cell (this is Replicate 1's reported figure in the main text; Replicate 2 is stated to be "nearly identical").
- **Accessions / direct download — confirmed live by `curl -I` on 2026-07-28**:
  - Xenium Replicate 1: `https://cf.10xgenomics.com/samples/xenium/1.0.1/Xenium_FFPE_Human_Breast_Cancer_Rep1/Xenium_FFPE_Human_Breast_Cancer_Rep1_outs.zip` — **HTTP 200, 9.86 GB**, `last-modified: 2022-12-06`.
  - Xenium Replicate 2: `https://cf.10xgenomics.com/samples/xenium/1.0.1/Xenium_FFPE_Human_Breast_Cancer_Rep2/Xenium_FFPE_Human_Breast_Cancer_Rep2_outs.zip` — **HTTP 200, 8.49 GB**, `last-modified: 2022-12-06`.
  - Visium CytAssist (same block): `https://cf.10xgenomics.com/samples/spatial-exp/2.0.0/CytAssist_FFPE_Human_Breast_Cancer/CytAssist_FFPE_Human_Breast_Cancer_filtered_feature_bc_matrix.h5` and `..._spatial.tar.gz`. (Not independently `curl`-verified in this pass — URLs sourced from the paper's official companion repo, see below; treat liveness as **UNVERIFIED** pending a direct check, though the sibling Xenium URLs on the same CDN pattern were confirmed live.)
  - Source of these exact URLs: 10x Genomics' own code companion to the paper, [github.com/10XGenomics/janesick_nature_comms_2023_companion](https://github.com/10XGenomics/janesick_nature_comms_2023_companion) — verified by direct fetch.
  - Output bundle format is the standard Xenium Onboard Analysis output (per-cell `cells.csv.gz`, `cell_feature_matrix` MEX triple, `transcripts.parquet`, morphology images) — this is exactly the layout `resolve_xenium_files()` in `ingest.py` looks for.
- **Ingestible by tme-sim today?** Yes for the Xenium layer, with no new code — it is the same Space Ranger/Xenium bundle shape the existing `xenium` and `visium` detectors already parse (the repo's own demo data, per `ingest.py`'s docstring, literally *is* a Xenium GBM equivalent of this same bundle shape).
- **Marker coverage**:
  - **MKI67 (proliferation)**: confirmed present on the 280/313-gene breast panel (10x Genomics panel documentation, cross-checked via web search — [10xgenomics.com/support panel docs](https://www.10xgenomics.com/support/software/xenium-panel-designer/latest/tutorials/pre-designed-xenium-v1)).
  - **PECAM1/CD31, COL1A1/COL1A2/COL3A1 (ECM), VEGFA/CA9/HIF1A (hypoxia), TOP2A (proliferation)**: presence on the specific 313-gene targeted Xenium panel is **UNVERIFIED** — the exact panel gene CSV was not directly fetched in this pass (10x gates it behind a downloadable metadata file, not inline HTML).
  - **Important mitigation**: the paired **Visium CytAssist data from the same block is whole-transcriptome** (18,536-gene FFPE probe set), so all of the above markers (PECAM1, collagen genes, VEGFA, CA9, HIF1A, MKI67, TOP2A) are near-certainly present there regardless of the Xenium targeted-panel question — meaning even if the Xenium layer is missing a marker, the co-registered Visium layer from the identical block is not.

### TIER 2 — PASTE2's own benchmark dataset, exact documented z-spacing, zero new ingestion code, but NOT cancer: DLPFC (spatialLIBD / Maynard et al.)

This is the dataset PASTE2's own paper uses to validate alignment accuracy against ground-truth (manually annotated cortical layers) — i.e., the method's authors treat this as the gold-standard real-data test case.

- **Paper (PASTE2's use of it, verified by direct full-text fetch)**: Liu X, Zeira R, Raphael BJ. "Partial alignment of multislice spatially resolved transcriptomics data." *Genome Research* 33(7):1124–1132 (2023). DOI: [10.1101/gr.277670.123](https://doi.org/10.1101/gr.277670.123). PMID: [37553263](https://pubmed.ncbi.nlm.nih.gov/37553263/), PMC: [PMC10538490](https://pmc.ncbi.nlm.nih.gov/articles/PMC10538490/).
- **Original data source**: Maynard EA, et al. (Kristen Maynard / Keri Martinowich / Andrew Jaffe / Stephanie Hicks group, LIBD), "Transcriptome-scale spatial gene expression in the human dorsolateral prefrontal cortex," *Nature Neuroscience* 2021. Public via the `spatialLIBD` Bioconductor package: [research.libd.org/spatialLIBD](https://research.libd.org/spatialLIBD/), [github.com/LieberInstitute/spatialLIBD](https://github.com/LieberInstitute/spatialLIBD).
- **Tissue**: human postmortem dorsolateral prefrontal cortex — **normal tissue, not cancer**. Still directly useful as a registration-pipeline shakedown target since it is exactly what PASTE2 itself validated against.
- **Sections / z-spacing — verbatim from PASTE2's own Methods (verified by direct fetch)**: 3 individuals (samples 1, 2, 3), 4 slices each (A, B, C, D), 12 slices total. *"For each individual, slice A and B are 10 µm apart, the same as slice C and D. Slice B and C are further apart at a distance of 300 µm, hence slice pairs AB and CD are more similar to each other than slice pair BC."* This is the most precisely documented z-spacing found in this entire survey.
- **Platform**: 10x Genomics Visium (original, non-CytAssist), whole-transcriptome.
- **Spot count**: ranges 3,460–4,789 spots per section across the 12 samples (exact per-sample counts confirmed via secondary source, [zhengli09.github.io/BASS-Analysis/DLPFC.html](https://zhengli09.github.io/BASS-Analysis/DLPFC.html) — **UNVERIFIED against the primary spatialLIBD source directly** in this pass, but internally consistent with the well-known dataset).
- **Ingestible by tme-sim today?** Yes — standard Space Ranger Visium output, matches `resolve_visium_dirs()` in `ingest.py` directly. Download via `spatialLIBD::fetch_data()` (R/Bioconductor) or the raw Space Ranger outputs mirrored on the LIBD GitHub.
- **Marker coverage**: whole-transcriptome Visium, so PECAM1, collagen genes, VEGFA/CA9/HIF1A, MKI67/TOP2A are all present in the assay — but this is **normal brain tissue**, so hypoxia/proliferation signal will be biologically minimal/absent (not diseased), useful for pipeline mechanics only, not for validating tumor-relevant biology.

### TIER 3 — PASTE2's headline 3D-reconstruction demo: 16-slice Stereo-seq Drosophila embryo (largest slice count found, but wrong species and platform not natively supported)

- **Paper**: same PASTE2 paper as above. Verbatim: *"We applied PASTE2 to analyze a Stereo-seq data set from a Drosophila embryo... PASTE2 3D reconstruction using all 16 slices from the embryo."*
- **Original data source**: Wang M, et al. "High-resolution 3D spatiotemporal transcriptomic maps of developing Drosophila embryos and larvae." *Developmental Cell* 2022. [cell.com/developmental-cell/fulltext/S1534-5807(22)00246-5](https://www.cell.com/developmental-cell/fulltext/S1534-5807(22)00246-5). Public database: **Flysta3D**, hosted on the STOmics DataBase (CNGB) — accession **CNP0002189**, dataset ID **STDS0000060**, [db.cngb.org/stomics/datasets/STDS0000060](https://db.cngb.org/stomics/datasets/STDS0000060) and [db.cngb.org/stomics/flysta3d](https://db.cngb.org/stomics/flysta3d/) — verified by WebSearch cross-referencing the CNGB page content directly.
- **Sections / z-spacing**: embryos at two late developmental stages (14–16 h and 16–18 h after egg laying), cryosectioned into **7–10 µm thick slices**, all captured on Stereo-seq chips. PASTE2 used 16 slices from the E14–16 sample for its full 3D reconstruction. This is the largest slice count of any dataset found in this survey — genuinely a "stack," not just a pair.
- **Cancer relevance**: none — Drosophila melanogaster, developmental tissue.
- **Platform**: Stereo-seq (BGI/STOmics), ~500 nm resolution, ~1,000 spots/slice, median ~2,000 UMI/spot per PASTE2's own description.
- **Ingestible by tme-sim today?** **No, not without new code.** Stereo-seq's native output (a GEM/bin matrix format) is neither a Xenium bundle, a Space Ranger Visium bundle, nor obviously a bare 10x-style MEX triple; it would need reshaping into the generic `mex_plus_coordinates` escape hatch in `ingest.py` at minimum, and possibly a dedicated parser. Flagging this explicitly per the task brief's instruction to check against what `ingest.py` already supports — this is the one top-tier PASTE2/STalign dataset that fails that check.

### TIER 4 — breadth across cancer types, confirmed-live, recent (2026): Cervilla et al. six-cancer-type multi-platform serial-section benchmark

Not from the PASTE2/STalign papers themselves, but found via direct GEO/benchmark search per the task's secondary strategy, and it is unusually good: real serial FFPE tumor sections, six cancer types, run across five platforms including two tme-sim already ingests.

- **Paper**: Cervilla S, et al. "A technical comparison of spatial transcriptomics platforms across six cancer types." *Genome Biology* 27, 22 (2026). DOI: [10.1186/s13059-026-03937-y](https://doi.org/10.1186/s13059-026-03937-y). PMID: [41526977](https://pubmed.ncbi.nlm.nih.gov/41526977/), PMC: [PMC12888464](https://pmc.ncbi.nlm.nih.gov/articles/PMC12888464/) — metadata confirmed via PubMed MCP.
- **Cancer types**: bladder, breast, colorectal, lung, lymphoma, ovarian — six matched FFPE human tumor samples, each profiled with **matched serial sections** across platforms.
- **Platforms benchmarked (same tumor, serial sections)**: Visium v1, Visium v2/CytAssist, Visium HD, Xenium (Multi-Tissue panel, 377 genes; also Xenium Prime, 5,000 genes, on the same sample), and CosMx (Universal Cell Characterization panel).
- **Accessions — confirmed live by `curl -I` on 2026-07-28**:
  - Xenium + CosMx data: Zenodo [10.5281/zenodo.20199229](https://doi.org/10.5281/zenodo.20199229) — **HTTP 200**. 27.1 GB across 10 files, CC-BY-4.0, includes matched H&E histology images, described as "Open" access.
  - Visium v1/v2-CytAssist/HD data: Zenodo [10.5281/zenodo.17999961](https://doi.org/10.5281/zenodo.17999961) — **HTTP 200**.
- **Section thickness / exact z-spacing between platform-matched sections**: **UNVERIFIED** — not stated in the abstract or the fetched Zenodo record summary; would need the paper's Methods section for the precise cutting-order/thickness. Caveat this dataset is designed for **cross-platform comparison on adjacent sections** (one section per platform, ~5 sections total per tumor spanning a small total z-range), not a many-slice z-stack for volumetric reconstruction the way the DLPFC or Drosophila datasets are — useful primarily as a cross-technology registration test (the same use case STalign demonstrated with its MERFISH-to-Visium alignment), less useful as a "build one continuous 3D tumor volume" source.
- **Ingestible by tme-sim today?** Partially — the Xenium and Visium v1/v2 layers should match existing detectors; Visium HD compatibility is **UNVERIFIED** per the ingest.py grep above; CosMx would need the generic MEX escape hatch or a new parser.
- **Marker coverage**: Visium layers are near-whole-transcriptome, so all requested markers are very likely present there. Xenium Multi-Tissue panel (377 genes) is documented as including *"select immune, proliferation, and tumor markers"* with MKI67 confirmed by cross-reference; PECAM1/collagen/VEGFA/CA9/HIF1A on that specific panel are **UNVERIFIED**.

## Recommendation: build tme-sim's first 3D reconstruction against the Janesick breast cancer Xenium Replicate 1 / Replicate 2 pair (Tier 1)

**Why this one, not the others:**

1. **Zero new ingestion code.** It is a standard Xenium Onboard Analysis output bundle — the same shape `ingest.py` already parses for the repo's own GBM demo data. DLPFC (Tier 2) is equally zero-new-code (standard Visium), but is normal brain tissue with no tumor biology to test the model's actual purpose against.
2. **Cancer-relevant**, unlike DLPFC or the Drosophila embryo.
3. **Confirmed live today** by direct HTTP check (both replicate bundles return 200 with multi-GB `content-length`, not dead links or 403s) — not a "should still be up" guess.
4. **It is the exact real-world cancer serial-section pair STalign itself chose to validate on** (STalign's Methods: *"Two Xenium datasets (In Situ Replicate 1 and In Situ Replicate 2) of a single breast cancer FFPE tissue block"*), so tme-sim would be reproducing a registration a peer-reviewed method has already been shown to work on — de-risking the first attempt considerably.
5. **Comes with a matched whole-transcriptome Visium CytAssist layer from the identical block**, which both backstops the marker-coverage gap on the Xenium targeted panel and gives tme-sim a second, richer registration target (cross-platform, the STalign MERFISH-to-Visium use case) once the same-platform Xenium-to-Xenium registration is working.
6. **It has direct precedent inside the reference material tme-sim already has**: `results/landscape_pathology_3d.md` independently flagged PASTE2/STalign's native operation on "spot/coordinate data... the same data type tme-sim already knows how to read" as the plausible near-term 3D path — this dataset is the concrete instance of that path with a pinned-down, live, cancer-relevant download today.

**What it will NOT give tme-sim**: a many-slice continuous z-stack (it's a pair, at an unconfirmed but presumably small — single-digit-to-tens-of-microns — z-offset, not the wide, precisely-documented 300 µm range the DLPFC data offers, nor the 16-slice range of the Drosophila data). If the near-term goal shifts from "prove the registration pipeline runs end to end on real cancer Xenium data" to "prove tme-sim can reconstruct a genuinely 3D volume with meaningful depth," the DLPFC 12-section set (Tier 2, exact 10 µm / 300 µm spacing, already Visium-ready) is the better second target, precisely because its z-spacing is the most rigorously documented of anything found in this survey — even though it costs the cancer-relevance property. A reasonable two-step plan: register the Janesick Xenium Rep1/Rep2 pair first (cancer, zero new code, days not weeks), then use DLPFC's 12 slices to stress-test the registration pipeline's behavior across a real, precisely-known z-range before ever needing to build a Stereo-seq or CosMx ingester.
